## 29 сентября · исправление по реальному operation trail (voice-opaque-replies-v3)

В логе клиента voice-queue-v2 ответы имеют ID resp_…, а вызовы — независимые chatcmpl-tool-…. Прежняя очередь ошибочно ожидала reply.done с ID fc-<call_id>. Три HTTP-ошибки 409/400 за 0,61–1,14 с оставались в tool.result.queued и не отправлялись; агент продолжал после таймаута. Это подтверждённый дефект клиента, пропущенный прежними mock-тестами. Новый экспорт Vercel содержит только Time range exceeds your billing plan limits и не позволяет установить конкретные ошибочные аргументы.

Теперь вызов связывается с фактическим ответом, в котором пришёл. Успешные результаты и ошибки отправляются в разрешённое idle-окно сразу после готовности HTTP; прерванные вызовы не возрождаются, новое высказывание не отменяет commit. Replay обезличенной последовательности из присланного лога до исправления не отправлял ничего, после — отправляет все три результата в момент их готовности. ID сессии, транскрипты и аудио в fixture не включены.

Для модели оставлен один способ изменения услуг (полный serviceIds) и дат (allowedDates); конфликтующие delta/range формы убраны только из голосовой схемы, публичный HTTP-контракт сохранён. Ошибки содержат актуальную версию заявки для исправления. Добавлен полезный режим «Type instead · hear replies»: настоящий голосовой ИИ и те же серверные инструменты без включения микрофона. Текст не создаёт evidence голосового подтверждения; окончательное действие подтверждается кнопкой.

Проверены 233/233 автоматических теста, TypeScript, ESLint изменённых голосовых файлов и Next.js production build. Vinext и живой проход после публикации проверяются отдельно; измерения реального ответа и физического звука пока не заявляются.

Документация, сверенная при расследовании: [client-side tools](https://www.assemblyai.com/docs/voice-agents/voice-agent-api/tools/client-side-tools), [events](https://www.assemblyai.com/docs/voice-agents/voice-agent-api/events-reference), [prompting](https://www.assemblyai.com/docs/voice-agents/voice-agent-api/prompting-guide). Фактические opaque reply IDs из лога приоритетнее предположения о префиксе в примере документации.
