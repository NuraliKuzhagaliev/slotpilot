## Жалоба на паузу после ответа · 28 сентября 2026

Код позволял потерять результат уже начатого инструмента: при новом `input.speech.started` очищалась очередь, а завершившийся HTTP-вызов отбрасывался по номеру речевой эпохи. Провайдер мог продолжать ждать `tool.result` до собственного таймаута. Теперь начатый вызов обязательно получает ответ после своего `reply.done`: для устаревшего чтения — явную ошибку `TURN_CHANGED`, для завершившегося сохраняющего действия — фактический результат. Отменённый провайдером вызов по-прежнему не отправляется. Ручное изменение запроса также больше не теряет результат уже начатого инструмента.

Дата вне действующего 30-дневного горизонта должна вызывать немедленное объяснение допустимых дат, а не дальнейший сбор времени. Это улучшение инструкций модели, не гарантированный результат живой речи.

## Что исправлено

- Зависание инструмента при порядке `reply.done → tool.call`: окно отправки результата больше не закрывается самим `tool.call`. Результат по-прежнему связан с собственным `fc-<call_id>`.
- Ошибочный JSON аргументов возвращает `tool.result` с ошибкой вместо молчания до таймаута провайдера.
- Запоздалое прерывание предыдущего ответа, включая ответ инструмента, не обрывает текущую речь. Отменённый результат не возвращается в разговор. Сохранённое действие продолжает сверяться по `actionId`.
- Старые обработчики микрофона и WebSocket не вмешиваются в повторный запуск.
- В аудиоплеере появился буфер 40 мс для неровной доставки PCM. Короткий пакет начинает играть не позднее 60 мс ожидания плюс один аудиоблок; окончание реплики снимает ожидание сразу. При реальном опустошении буфер набирается снова. Сохраняются плавный вход, затухание и непрерывность ресэмплера.
- Латентность в интерфейсе теперь отсчитывается до события начала рендеринга аудио, а не до получения сетевого пакета. Аппаратную задержку динамика этот показатель не измеряет. В диагностике появились события опустошения буфера и безопасный код ошибки провайдера.
- Модель получает результат операции и текущую версию запроса без дублирующего UI-снимка и истории событий. Номера, версии и детали существующих записей сохраняются для их обсуждения и изменения. UI продолжает получать полный серверный ответ.
- Обычные ответы ограничены коротким предложением/вопросом, обычно до 30 слов. Обязательное полное чтение деталей перед отдельным подтверждением сохранено.
- Английскому распознаванию добавлен контекст автосервиса с услугами, автомобилями и филиалами. Частые слова и целые фразы убраны из списка усиления отдельных терминов.
- Исправлена предыдущая блокировка запуска: 10 попыток за 10 минут, возврат суточной квоты при неудачной выдаче токена, время следующей попытки для личного суточного лимита. Попытки в одной миллисекунде различаются, чтобы возврат одной не удалял успешную другую. Суточные защитные лимиты остаются действующими.

Схемы бизнес-контрактов, SQL-транзакции, проверки владельца, версии, отдельное подтверждение и `pnpm-lock.yaml` сохранены.

## Что ещё необходимо проверить перед приёмкой

Локальный серверный ключ AssemblyAI отсутствует. Авторизованная живая сессия пользователя в браузерной проверке недоступна. Поэтому исправления **не объявлены полной приёмкой P0** и стабильные ответы за 1–2 секунды не обещаются.

После деплоя провести один английский разговор с несколькими обменами:

1. «I need an oil change tomorrow for a petrol sedan, and I need the car ready before four». Проверить распознанные условия и предложение без повторного сбора уже названных данных.
2. Во время ответа сказать «Actually, make that after lunch at North». Проверить обрыв прежней речи, непрерывность нового ответа и обновление условий.
3. Произнести короткое «uh-huh» во время ответа: оно не должно самостоятельно очищать плеер, пока провайдер не подтвердил перебивание.
4. Дойти до чтения полного предложения. «Yes, but add a brake inspection» должно изменить условия, а не подтвердить прежнюю запись. Сохранение допускается только после отдельного финального подтверждения нового предложения.
5. Остановить разговор и один раз запустить снова. При ошибке сохранить её текст и события в Show operation trail; не расходовать квоту многократными перезапусками.

Личные/общие суточные квоты, доступность AssemblyAI и состояние сети остаются внешними ограничениями. Новый код не снимает уже накопленные старые лимиты и не пополняет баланс провайдера.
