# SlotPilot · этап 0

**Статус: написан и автоматически проверен локальный модуль проверки голоса. Живой прогон с AssemblyAI ещё не выполнен. Полное приложение записи на автосервис ещё не реализовано.**

Это первый небольшой этап из `docs/SPEC_RU.md`, а не замена согласованного проекта. Цель — проверить именно Voice Agent API на вашем аккаунте: микрофон → агент → `get_services` → сервер → ответ инструмента → голос. Пока нет доступа к настоящему ключу в окружении разработчика, факт работоспособности этого пути не утверждается.

## Что находится в архиве

Серверная выдача временного токена, inline-конфигурация английского агента, браузерные аудиомодули, очередь результатов инструментов, субтитры, адаптивный экран проверки, демонстрационный каталог и два тестовых пользователя. Экран различает полученные события, выполненный серверный инструмент и ручное подтверждение того, что голос действительно слышен.

`get_services` действительно выполняется локальным сервером. Возвращаются тестовые цены, длительности и совместимость автомобилей из ТЗ. Записей в автосервис он **не создаёт**. В рабочем приложении этого этапа нет скрытого mock-провайдера, фиктивного календаря или сообщения о несуществующем бронировании.

Подбор времени, PostgreSQL/Supabase, подготовка/подтверждение записи, admin/demo и P1 ещё не реализованы. Небольшой модуль Node.js без зависимостей выбран для изолированной проверки доступа, как подход официального JS starter. Это не Next.js-приложение. Основной согласованный стек Next.js + TypeScript + Tailwind + Supabase/PostgreSQL + Vitest + Playwright не меняется и относится к следующему этапу после проверки доступа. Официальный starter изучен; его живой запуск в этой среде не выполнен.

## Запуск на ноутбуке

Нужен Node.js **22.16.0 или новее** и браузер с микрофоном. Версия среды, использованной для автоматических тестов, — Node.js 22.16.0. Установка npm-зависимостей для этого этапа не требуется.

Распакуйте архив, откройте папку `slotpilot` в VS Code. В терминале **из этой папки**:

```sh
npm run setup
```

Команда создаст `.env.local`, сохранив туда разные случайные пароли пользователей `client` и `admin`. Если файл уже существует, команда не перезапишет его. Ни ключи, ни пароли в вывод терминала не печатаются.

Откройте `.env.local` в редакторе и заполните только строку вашего ключа:

```dotenv
ASSEMBLYAI_API_KEY=ваш_настоящий_ключ
```

Не вставляйте ключ в чат, браузерную консоль, `agents/`, `.env.example` или GitHub. Скопируйте значение `DEMO_CLIENT_PASSWORD` из того же локального файла для входа в интерфейс. Пароль администратора этому прогону не нужен.

```sh
npm run doctor
npm run dev
```

Откройте `http://localhost:3000`. Войдите как `client`, подтвердите передачу микрофонного аудио AssemblyAI и нажмите **Start voice check**. При другом `PORT` используйте адрес из терминала.

Первая фраза:

> What services do you offer for a petrol sedan?

Когда агент говорит, перебейте:

> Wait, tell me only about oil changes.

Должны появиться субтитры и каталог с сервера. Отдельно проверьте, что голос слышен и старый ответ прекращается при перебивании. Только после собственной проверки отметьте два ручных пункта. Затем нажмите Stop и **Export this check’s evidence**. Полный сценарий и разбор ошибок — в `docs/LIVE_CHECK_RU.md`.

Без API-ключа разрешена ручная проверка каталога после входа, но голос отключён. Такая проверка не считается успешной голосовой интеграцией. Проверка наличия ключа в `doctor` также не проверяет права или кредиты аккаунта.

## Проверки

```sh
npm run check
npm test
```

Эти команды не обращаются к AssemblyAI и не используют настоящий ключ. В тестах выдачи токенов и событий применены явно выделенные фикстуры. HTTP-тесты запускают настоящий локальный Node-сервер.

Точные границы и сохранённый тестовый вывод — `docs/VERIFICATION_RU.md` и `docs/verification/`. Скриншоты в этой папке являются **статическим предпросмотром**, не доказательством работы приложения или голоса.

Дополнительный браузерный тест: `python tests/browser_smoke.py`. Он требует отдельно установленного Python Playwright и Chromium; браузер должен разрешать локальные страницы и тестовое аудиоустройство. Голосовой сценарий в этом тесте использует явно обозначенный mock, а не AssemblyAI. Путь к установленному Chromium можно передать через `CHROMIUM_PATH`. Встроенные ограничения управляемого браузера не обходить. Статический рендер запускается отдельно: `python tests/render_static_preview.py`.

## Секреты, расходы и границы безопасности

- Настоящие секреты хранятся только в `.env.local`, который исключён из Git. В архиве есть только пустой `.env.example`. Не используйте переменные с префиксом `NEXT_PUBLIC_` для ключа.
- Веб-сервер слушает только `127.0.0.1` и проверяет Host/Origin. Для тестового входа используются HttpOnly/SameSite cookies; роли назначает сервер. В браузер выдаётся временный голосовой токен, а не постоянный ключ.
- По умолчанию: окно использования токена 60 секунд, голосовая сессия до 180 секунд, 3 попытки выдачи за 10 минут на тестового пользователя, 20 попыток на процесс. Неудачные обращения тоже расходуют лимит попыток.
- Авторизация, лимиты и кэш вызовов находятся **в памяти одного локального процесса**. После перезапуска они сбрасываются. Это не промышленная авторизация, не долговременный журнал и **не гарантированный денежный лимит**. Перед живым тестом проверьте тариф, доступ и кредиты аккаунта. Нажатие запуска голоса может расходовать ваши кредиты. Автотесты и обычный запуск сервера платных API-вызовов не делают.
- Не публикуйте этот модуль в интернете и не открывайте его через туннель. Cookie рассчитана на локальный HTTP; для развёртывания нужны основное приложение, HTTPS, постоянная авторизация и серверные лимиты, сохраняющиеся между процессами.
- Приложение дополнительно не записывает аудио на диск; субтитры хранятся в текущей вкладке. Политику и настройки хранения на стороне провайдера нужно проверить отдельно. Для прогона используйте вымышленные данные. Экспорт проверки не включает аудио, тексты реплик, токены, ключи или пароли.

## Где что находится

```text
agents/voice-access.mjs              английский prompt и inline-конфигурация
spikes/voice-access/server.mjs       локальные HTTP endpoints и серверные проверки
spikes/voice-access/provider.mjs     запрос временного токена AssemblyAI
spikes/voice-access/catalog.mjs      демонстрационные серверные данные
spikes/voice-access/shared/          контракт только этого этапа
spikes/voice-access/public/          экран, аудио, WebSocket, очередь tools
scripts/                            setup, doctor, check
tests/                             модульные, HTTP и дополнительные UI-тесты
docs/                              ТЗ, архитектура, статус, живой прогон
```

Контракт пробного `get_services` не выдаётся за уже утверждённый `src/contracts/domain.ts` полного продукта. До параллельной разработки основного приложения общий каталог схем нужно утвердить и создать один раз у интегратора B.

## Следующий проверяемый результат

Сначала подтвердить живой Voice Agent доступ и один серверный вызов на вашем ноутбуке. Затем согласовать репозиторий, Supabase, срок хакатона и обязательность LLM Gateway. После этого — каркас основного приложения и первый путь с одной услугой: условия → подбор → подготовка → явное подтверждение → транзакционная запись → чтение после перезагрузки.

Этот архив не создаёт репозиторий, облачную базу, stored agent или платные ресурсы. Правила команды и предстоящие границы владения описаны в `docs/TEAM_OWNERSHIP_RU.md`; инструкции для следующего ИИ — `AGENTS.md`.
