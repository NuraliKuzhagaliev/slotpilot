# Работа трёх участников

Это подготовка к разделению **основного** приложения, а не утверждение, что три модуля уже созданы. Сейчас один изолированный этап 0. До параллельного написания основного кода интегратор B фиксирует общий каркас, контракт и версии зависимостей.

| Участник | Будущие разрешённые области |
|---|---|
| A — интерфейс | `src/features/booking-ui/`, `src/features/admin-ui/`, `src/components/ui/`, согласованные страницы клиента/admin/demo |
| B — голос и интеграция | `src/features/voice/`, `src/server/voice/`, `src/app/api/voice/`, `src/app/api/tools/`, `agents/`, `public/audio/` |
| C — бизнес-логика и БД | `src/server/domain/`, `src/server/db/`, `src/app/api/requests/`, `src/app/api/admin/`, `src/app/api/demo/`, `supabase/` |

B владеет `src/contracts/`, root-конфигами, package.json/lockfile, layout, CI и AGENTS.md. C владеет миграциями и seed. Изменение чужой области или контракта согласуется до коммита. Точные пути страниц закрепить в стартовом каркасе, чтобы общий layout не оказался в двух ветках.

Материалы этого этапа принадлежат интеграционной ветке B. A не превращает access-probe UI в отдельный production frontend. C не создаёт второй voice transport. Проверенный адаптер переносится в единое приложение; probe после перехода остаётся диагностическим артефактом или удаляется отдельным согласованным изменением.

Работа — в отдельных feature-ветках с небольшими PR, без force-push в общую ветку. До интеграции — тесты и сборка. У каждого участника отдельное окружение/namespace БД, отдельный `.env.local`; секреты не передаются через git или архивы.

Формат задачи ИИ: цель, границы файлов, вход/выход по общему контракту, критерии приёмки, тесты. После задачи: фактические изменения, запущенные проверки, результат и блокеры. Недоступность внешнего сервиса не скрывать через фиктивный успех.

Следующий совместный контрольный результат после этапа доступа: одна услуга → серверный подбор → PreparedAction → отдельное согласие → PostgreSQL-транзакция → чтение реальной записи после обновления страницы. Не начинать три независимых проекта.
