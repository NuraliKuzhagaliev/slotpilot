# Статус реализации · 23 сентября 2026

## Ближайшая задача

**Цель:** подготовить проверку доступа к AssemblyAI Voice Agent API по разделам 6.4 и 14 ТЗ.

**Разрешённые файлы этого этапа:** `spikes/voice-access/`, `agents/voice-access.mjs`, `scripts/`, `tests/`, документация, начальные локальные root-конфиги. Основное приложение Next.js и миграции БД не создаются до снятия блокеров этапа доступа.

**Вход:** локальный серверный ключ, автоматически подготовленные тестовые пароли, английская речь и разрешение микрофона.

**Выход:** слышимый диалог, финальная расшифровка, фактический `get_services` с сервера, корректное прекращение старого звука при перебивании, завершение сессии и экспорт наблюдений без секретов.

**Критерий приёмки:** живой прогон этого пути на реальном аккаунте. Автоматические тесты и статические изображения его не заменяют.

## Нерешённые внешние вопросы

Нужны подтверждение реального Voice Agent доступа, реальный микрофон и проверка слышимого ответа. Ключ в этой среде не предоставлен; пользователь вводит его только локально. Наличие ключа само по себе не подтверждает права, кредиты или качество диалога.

Также не известны выбранный GitHub-репозиторий, наличие проекта Supabase, срок сдачи, обязательность LLM Gateway по регламенту и допустимый бюджет живых тестов. Они не были подменены предположениями. Репозиторий и внешние ресурсы не создавались.

## Отклонения от основной реализации — открыто

Пробный сервер использует Node.js и встроенный test runner вместо Next.js/Vitest. Это изолированный этап 0, а не изменение стека итогового приложения. В этой среде установка npm-зависимостей через интернет недоступна. Официальный starter и протокол изучены, но его запуск с реальным аккаунтом не выполнен. Основные версии зависимостей и lockfile приложения Next.js предстоит зафиксировать отдельно.

Контракты всего P0, транзакции, версии запросов и роли постоянных учётных записей ещё не объявляются готовыми. Защита повторов `get_services` не является проверкой идемпотентности бронирования.

**Разрешающий следующий этап результат:** подтверждённый живой цикл с инструментом. После него — общий каркас и безопасный первый путь с настоящей PostgreSQL. Принцип «LLM озвучивает, сервер рассчитывает, БД хранит» остаётся неизменным.
